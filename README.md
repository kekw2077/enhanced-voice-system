# Nexus Anima

**Nexus Anima** (прежнее имя — EVS, Enhanced Voice System) — десктопный голосовой
ассистент для **Windows**: постоянное прослушивание со словом-активатором, выполнение
команд, распознавание и синтез речи, чат с ИИ (локально, через свой сервер или на
домашней станции), студии генерации картинок и озвучки, плавающий виджет с живой
визуализацией голоса.

> Только Windows. Установщик компактный (~17 МБ), тяжёлые компоненты (голосовой
> движок, клонирование голоса) догружаются по требованию. Автообновления — через
> собственный подписанный канал.

## Возможности

### Голос
- **Слово-активатор** «Anima» (распознаётся и в русской, и в английской речи),
  постоянное прослушивание, озвучка ответов, Push-to-Talk на выбранной клавише.
- **Распознавание речи (STT):** Whisper (мультиязычный, выбор размера модели),
  GigaAM (русский, точнее на русской речи) и подключение к чужому серверу по
  контракту OpenAI. Движок ставится отдельным компонентом при первом включении голоса.
- **Синтез речи (TTS):** голоса Piper, системный голос Windows и **клонирование
  голоса** — ответы вашим голосом из образца WAV на 6–10 секунд. Клон работает двумя
  серверами по ролям: лёгкий на процессоре озвучивает живой разговор, тяжёлый на
  видеокарте — студию озвучки.
- **Каталог голосовых команд:** открытие приложений, ярлыков (`.lnk`), файлов и
  ссылок, управление медиа и громкостью, громкость отдельных программ; видимый
  отклик (что услышано, статус движка, уведомления о выполнении).

### ИИ-чат
- **Удалённый режим** — подключение к любому Ollama- или OpenAI-совместимому API
  (домашняя станция, локальная сеть, свой сервер).
- **Локальный режим** — инференс прямо на устройстве через
  [fllama](https://github.com/Telosnex/fllama) (llama.cpp, GGUF-модели), полностью
  офлайн. Встроенный каталог моделей разбит на тиры по мощности устройства.
- Несколько диалогов с историей, поиском и закреплением; персонализация ассистента
  (тон, формальность, многословность и т. п.) и память/профиль «о вас».

### Студии
- **Nexus Lumina** — генерация картинок на домашней станции: выбор модели и LoRA,
  ход работы по шагам, очередь кадров.
- **Nexus Sonora** — озвучка текста своим голосом: длинный текст режется на куски,
  считается по одному и собирается в один файл, с настоящим счётчиком «кусок 7 из 18».
- Видеокарта на станции одна, поэтому студии и разговор **договариваются об очереди**:
  открытая студия снимает языковую модель с карты, закрытая — возвращает.

### Десктоп-оболочка
- **Четыре стиля оформления** — классический, Nexus, «Ноктюрн» и «Призма».
- **Плавающий виджет** — отдельное всегда-поверх окно с живой визуализацией голоса
  (волна/сфера/кольцо/полосы/частицы), реагирующей на речь и озвучку.
- **Системный трей**, глобальные горячие клавиши, автозапуск при входе в систему,
  собственная безрамочная тема окна.
- **Шина событий**: запуск игры из списка переключает звук на наушники (или спрашивает
  об этом вслух), приглушает музыку, возвращает всё при выходе.
- **Удалённый ввод с телефона** — отправка команд и текста по локальной сети.
- **Переводчик игры** — перевод текста поверх стороннего приложения.
- Метрики системы (CPU/RAM/VRAM) в боковой панели, интерфейс RU/EN.

### Обновления
- Тонкие обновления: компактный установщик + догрузка тяжёлых компонентов по
  требованию. Автообновления через собственный канал (appcast + **подписанные**
  установщики), окно «Что нового» со списком изменений, откат на прошлую версию.

## Системные требования

Требования зависят от режима: удалённый LLM нетребователен к железу, локальные
модели и офлайн-распознавание требуют больше памяти и (желательно) видеокарты.

### Минимальные
- **ОС:** Windows 10 64-bit (версия 1809 или новее) или Windows 11.
- **CPU:** двухъядерный x64.
- **ОЗУ:** 4 ГБ (удалённый режим, лёгкая работа).
- **Диск:** ~500 МБ на приложение + ~1–2 ГБ на голосовой движок (догружается при
  включении голоса); плюс место под локальные модели, если используете их.
- **Микрофон** — для голосового ввода и слова-активатора.
- **Интернет** — для удалённых моделей и первичной загрузки компонентов/моделей
  (в чистом офлайне после загрузки не обязателен).

### Рекомендуемые
- **ОС:** Windows 11 64-bit.
- **CPU:** современный 4+ ядерный x64.
- **GPU:** дискретная видеокарта — заметно ускоряет локальный инференс и офлайн-
  распознавание (не обязательна).
- **ОЗУ:** 16 ГБ. Локальные LLM 7–8B в квантовании Q4 занимают дополнительно
  ~5–6 ГБ; больше памяти — крупнее модель и контекст.
- **Диск:** SSD; запас под модели (GGUF-модели — от ~0.5 до ~5 ГБ каждая).
- Отдельный микрофон/гарнитура — для стабильного распознавания.

Студии картинок и озвучки, а также быстрый чат считаются **не на этом компьютере**, а
на домашней станции с видеокартой — её требования к приложению не относятся.

> Полностью офлайн-работа возможна (локальная модель + офлайн STT/TTS), но требует
> места под модели и больше RAM/GPU. Удалённый режим минимально требователен к железу.

## Установка и обновления

1. Установщик `NexusAnima-Setup-x.y.z.exe` (у прежних выпусков —
   `EVS-Setup-x.y.z.exe`) запускается как обычная программа; права администратора не
   нужны, по умолчанию ставится в профиль пользователя.
2. При первом включении голосовых функций Anima догрузит голосовой движок.
3. Дальше приложение обновляется само: новые версии приходят из собственного канала,
   появляется окно «Что нового» — обновление применяется в один клик. Установщик
   проверяется по подписи, неподписанное обновление не ставится.

## Технологии

Flutter (Windows desktop), прямые вызовы Win32 (трей, горячие клавиши, управление
окном, single-instance), локальный инференс через fllama (llama.cpp), офлайн
распознавание и синтез речи через отдельный компонент на Python, автообновление в
стиле Sparkle (WinSparkle / `auto_updater`) с подписанными установщиками. Тяжёлые
модели (языковая, клон-голос, генерация картинок) живут в контейнерах на домашней
станции с AMD-видеокартой под ROCm.

Проект — одна кодовая база; Flutter-приложение находится в подпапке
[`test1/`](test1/). Карта проекта для разработки — [`test1/CLAUDE.md`](test1/CLAUDE.md).

## Статус

Персональный проект, только Windows. Прежнее имя EVS сохраняется в служебных
идентификаторах (имя движка, переменные окружения, ключи обновлений) — это
намеренно, чтобы уже установленные копии продолжали обновляться.
