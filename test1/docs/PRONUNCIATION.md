# Ударения и произношение в озвучке

Как заставить движки говорить «тво́рог», а не «творо́г», и читать «Nvidia» как
«энвидиа». Всё, что ниже про Piper, проверено на живом espeak-ng (фонемы в примерах —
его реальный вывод), а не пересказано по памяти.

## Коротко: кто чем управляет

| Движок | Где он работает | Кто решает ударение | Что можно сделать |
|---|---|---|---|
| **Piper** (sherpa-onnx, VITS) | процессор | словарь espeak-ng `ru_dict` — 843 тыс. словоформ с пометкой ударного слога | дописать свои слова в словарь и пересобрать его — **ударение ставится гарантированно** |
| **Системный голос** (SAPI5 / pyttsx3) | процессор | Windows, закрыто | только подмена слов в тексте |
| **XTTS-v2** (`xtts_server.py`, `clone_worker.py`) | видеокарта / процессор | сама нейросеть | только подмена слов в тексте; ударение — «как поймёт» |
| **Qwen3-TTS, CosyVoice2** (клон-сервер) | видеокарта | сама нейросеть | то же, что XTTS |

Знаки ударения **в самом тексте** (`тво́рог`, `твОрог`, `тв+орог`, `тво'рог`) Piper
**не понимает** — espeak-ng их молча выбрасывает, слово читается как обычно. Это
проверено, не тратьте на это время. Для нейросетевых движков такой знак иногда
помогает, но чаще ломает слово (см. ниже).

## 1. Piper — свой словарь ударений

### Как это устроено

Голос Piper лежит в `<папка установки>\userdata\models\<id голоса>\` и состоит из
`<голос>.onnx`, `tokens.txt` и папки `espeak-ng-data\`. Текст сначала проходит через
espeak-ng, который по файлу `espeak-ng-data\ru_dict` превращает буквы в фонемы и
ставит ударение, и только потом нейросеть озвучивает фонемы. `ru_dict` — скомпилированный
бинарник; исходники к нему лежат в репозитории espeak-ng:

- `dictsource/ru_list` — числа, служебные слова, исключения;
- `dictsource/extra/ru_listx` — те самые 843 тысячи словоформ (≈5 МБ);
- `dictsource/ru_rules` — правила чтения букв;
- `dictsource/ru_emoji` — эмодзи.

Компилятор дополнительно читает файл `ru_extra`, если он есть, — и его записи
**перекрывают** всё, что было в `ru_list`/`ru_listx`. В него и пишем свои слова.

### Формат `ru_extra`

Файл в UTF-8, одна запись на строку: слово, затем табуляция или пробелы, затем
что с ним делать. Регистр слова не важен (`Nvidia`, `NVIDIA`, `nvidia` — одно и то же).

**Вариант А — только ударение.** `$N` — номер ударного слога (считаются гласные):

```
замок        $1          → зáмок      (по умолчанию espeak читает «замóк»)
творог       $1          → твóрог
звонит       $2          → звони́т
обеспечение  $4          → обеспечéние
```

Проверка фонемами: `творог` было `t_v_ʌ_r_ˈo_k`, стало `t_v_ˈo_r_ʌ_k` (`ˈ` стоит
перед ударной гласной).

**Вариант Б — полная транскрипция.** Нужна, когда неправильно не только ударение:
латиница, аббревиатуры, заимствования. Пишется фонемами espeak-ng, `'` ставится
**перед ударной гласной**:

```
nvidia       Env;'id;ia          → энви́диа
gpu          dZ;ip;i'ju          → джипию́
steam        st'im               → стим
```

Фонемы для русского (проверено на компиляции):

| Запись | Звук | Пример записи → как читается |
|---|---|---|
| `a A o u y i I E e` | гласные; `V` — безударная а/о («ъ-образная»), `I` — безударная и/е | `m'am;V` → мáмя |
| `'` | ударение, перед гласной | `zvVn;'it` → звони́т |
| `;` после согласной | мягкость | `l;'ol'a` → лёла; `p'Ip;I` → пи́пи |
| `j` | й | `j'olkV` → ёлка; `sj'ezd` → съезд |
| `S Z tS; S;S; ts x` | ш ж ч щ ц х | `tS;'aS;S;'a` → чáщá; `ts'ox'y` → цóхы́ |
| `r; l; n; t; d; s;` и т.д. | мягкие р л н т д с | `r;'ir'y` → ри́ры́ |

Полный список — в `ru_list` (там же примеры на числа) и в файле
`phsource/ph_russian` репозитория espeak-ng.

**Словоформы.** Словарь знает формы, а не леммы. Чтобы «твóрог» звучал правильно во
всех падежах, нужны отдельные строки: `творог $1`, `творога $1`, `творогу $1`,
`творогом $1`, `твороге $1`. Для имён собственных и аббревиатур обычно хватает
одной-двух форм.

### Сборка словаря

Консольный `espeak-ng` не нужен: компилятор есть внутри DLL, а DLL со всеми данными
ставится одной командой из PyPI. Один раз:

```powershell
python -m venv espk
espk\Scripts\pip install espeakng-loader
mkdir dictsource
cd dictsource
curl -sLO https://raw.githubusercontent.com/espeak-ng/espeak-ng/master/dictsource/ru_list
curl -sLO https://raw.githubusercontent.com/espeak-ng/espeak-ng/master/dictsource/ru_rules
curl -sLO https://raw.githubusercontent.com/espeak-ng/espeak-ng/master/dictsource/ru_emoji
curl -sLO https://raw.githubusercontent.com/espeak-ng/espeak-ng/master/dictsource/extra/ru_listx
cd ..
```

Рядом положите `dictsource\ru_extra` со своими словами и скрипт `build_ru_dict.py`:

```python
"""Пересобирает ru_dict для голоса Piper из dictsource/ (включая ru_extra).

    python build_ru_dict.py "<папка установки>\\userdata\\models\\<голос>\\espeak-ng-data"

Без аргумента собирает в espeak-ng-data самого пакета espeakng-loader — годится,
чтобы проверить словарь фонемами (check_ru.py), не трогая голос.
"""
import ctypes, os, shutil, sys
import espeakng_loader as l

data = sys.argv[1] if len(sys.argv) > 1 else str(l.get_data_path())
dst = os.path.join(data, "ru_dict")
if os.path.exists(dst) and not os.path.exists(dst + ".orig"):
    shutil.copy(dst, dst + ".orig")            # резервная копия исходного словаря

crt = ctypes.CDLL("ucrtbase")                  # FILE* для лога должен быть из CRT самой DLL
crt.fopen.restype = ctypes.c_void_p
crt.fopen.argtypes = [ctypes.c_char_p, ctypes.c_char_p]
crt.fclose.argtypes = [ctypes.c_void_p]
log = crt.fopen(b"compile.log", b"w")

lib = ctypes.CDLL(str(l.get_library_path()))
lib.espeak_ng_InitializePath(data.encode())    # phontab берётся отсюда — ВАЖНО, чтобы это была папка голоса
lib.espeak_ng_Initialize(None)
assert lib.espeak_ng_SetVoiceByName(b"ru") == 0, "голос ru не найден в data path"
lib.espeak_ng_CompileDictionary.argtypes = [ctypes.c_char_p, ctypes.c_char_p,
                                            ctypes.c_void_p, ctypes.c_int, ctypes.c_void_p]
status = lib.espeak_ng_CompileDictionary(b"dictsource/", b"ru", log, 0, None)
crt.fclose(log)
print("status", status, "->", dst, os.path.getsize(dst), "байт")
print(open("compile.log", encoding="utf-8", errors="replace").read())
```

Запуск: `espk\Scripts\python build_ru_dict.py "<...>\espeak-ng-data"`. В логе должно быть
`Compiling: 'dictsource/ru_extra'` с числом записей и `status 0`. Ошибка в строке
`ru_extra` печатается в лог с номером строки — словарь при этом всё равно собирается,
просто без этой записи.

Обязательно:

1. **Data path — папка `espeak-ng-data` самого голоса**, не пакета из PyPI. Словарь
   хранит номера фонем из `phontab`, и таблицы должны совпадать. Готовый `ru_dict`
   компилятор кладёт в ту же папку.
2. Перед первой сборкой скрипт сам сохраняет `ru_dict.orig` — это откат.
3. После замены словаря **перезапустить движок** (в настройках Anima перезапуск
   движка, либо перезапуск программы): sherpa-onnx читает `ru_dict` при загрузке голоса.
4. Обновление голоса (переустановка, новая версия пакета) затирает `espeak-ng-data`
   вместе со словарём — `ru_extra` держите отдельно и пересобирайте.

Если после подмены словаря Piper молчит или лог движка ругается на словарь —
версия espeak-ng внутри sherpa-onnx (форк piper-phonemize) разошлась с версией из
PyPI. Тогда вернуть `ru_dict.orig` и собирать той же версией: скачать исходники
espeak-ng того же тега, что использует piper-phonemize, и собрать `espeak-ng.dll`
из них. На момент написания такой проблемы не встречалось, но проверка на живом
голосе ещё не делалась — первый запуск делайте с оглядкой.

### Проверка без прослушивания

`check_ru.py` печатает фонемы так, как их увидит нейросеть. Ударная гласная помечена `ˈ`:

```python
import ctypes, sys
import espeakng_loader as l
data = sys.argv[1] if len(sys.argv) > 1 else str(l.get_data_path())
lib = ctypes.CDLL(str(l.get_library_path()))
lib.espeak_Initialize(0x0002, 0, data.encode(), 0)
lib.espeak_SetVoiceByName(b"ru")
lib.espeak_TextToPhonemes.restype = ctypes.c_char_p
lib.espeak_TextToPhonemes.argtypes = [ctypes.POINTER(ctypes.c_void_p), ctypes.c_int, ctypes.c_int]
for word in sys.stdin.read().split():
    buf = ctypes.c_char_p(word.encode("utf-8"))
    p = ctypes.cast(ctypes.pointer(buf), ctypes.POINTER(ctypes.c_void_p))
    print(f"{word:24} {lib.espeak_TextToPhonemes(p, 1, 0x02 | (ord('_') << 8)).decode()}")
```

```powershell
$env:PYTHONIOENCODING = "utf-8"
"замок творог nvidia" | espk\Scripts\python check_ru.py "<...>\espeak-ng-data"
```

Первый аргумент — та же папка `espeak-ng-data`; без него проверяется словарь пакета.

## 2. XTTS и остальные нейросетевые клоны — подмена текста

У XTTS-v2 (и у Qwen3-TTS, CosyVoice2) нет словаря: модель читает текст «по опыту».
Управлять можно только тем, какой текст она получит. Что реально помогает, в порядке
надёжности:

1. **Латиница → кириллица по звучанию.** В русском режиме XTTS читает латиницу
   неровно: `Nvidia` → «энвидиа», `GPU` → «джи-пи-ю», `Steam` → «стим», `Discord` → «дискорд».
2. **Аббревиатуры — по буквам через дефис:** `USB` → «ю-эс-би», `ЦПУ` → «цэ-пэ-у».
   Без дефисов модель пытается прочитать их как слово.
3. **«ё» всегда писать явно.** `все`/`всё`, `небо`/`нёбо` — без точек модель гадает.
4. **Числа — словами**, особенно с падежом: «в две тысячи двадцать шестом году».
   Автораскрытие чисел у XTTS русские падежи не знает.
5. **Ударение — переформулировать.** Знак `́ ` (U+0301) в текст лучше не вставлять:
   в словаре BPE-токенизатора XTTS такого символа, судя по всему, нет, слово
   разбивается на осколки и звучит хуже, чем без знака. Если модель упорно говорит «звóнит», надёжнее заменить слово
   («позвонит» → «наберёт»), чем бороться. Для Qwen3-TTS и CosyVoice2 знак ударения
   можно попробовать — заранее неизвестно, результат надо слушать.
6. **Очень короткие реплики** («Да», «Нет») XTTS проглатывает — `clone_worker.py` уже
   дописывает к ним ` …`, руками ничего делать не надо.

Важно: XTTS сначала прогоняет текст через свой очиститель (`multilingual_cleaners`):
всё в нижний регистр, символы `[ ] ( ) < > "` вырезаются. Поэтому «ЗАМОК» для
выделения ударения не работает, а скобки в подсказке произношения просто исчезнут.

### Где эта подмена должна жить в Anima

Сейчас в программе нет словаря замен — всё выше делается руками в тексте команд и
подсказок. Задел на реализацию (не сделано):

- **Один файл** `<userdata>\pronounce.txt`, строка = `что → как`:
  ```
  nvidia → энвидиа
  gpu → джи-пи-ю
  творог → твОрог
  ```
  Заглавная буква (или `+` перед гласной) — метка ударения.
- **Для всех движков** sidecar подменяет слова в тексте перед синтезом — одно место,
  [tts_engine.py](../sidecar/tts_engine.py) `_play_one()`, до вызова
  `engine.synthesize()`. Замена по целому слову, без учёта регистра; метка ударения
  из замены убирается (нейросети её видеть не должны).
- **Для Piper** из того же файла генерируется `ru_extra`: `твОрог` → `творог $2`
  (номер = порядковый номер помеченной гласной), `nvidia → энвидиа` → замена в тексте
  (транскрипцию в фонемы espeak руками писать не заставляем). Затем сборка `ru_dict`
  скриптом из раздела 1, встроенным в sidecar (`espeakng-loader` — одна зависимость,
  DLL ≈ 0,4 МБ + данные ≈ 19 МБ; исходники словаря ≈ 24 МБ качаются один раз
  в `<userdata>\espeak-dictsource`), и перезагрузка `PiperEngine`.
- Формы слов для Piper: на первой версии — только те, что пользователь вписал; позже
  можно генерировать падежи по простым шаблонам.

## 3. Системный голос Windows (SAPI5)

Управляется только подменой текста (раздел 2, пункты 1–4). SAPI умеет принимать
фонемы через XML (`<pron sym="...">`), но pyttsx3 передаёт текст с флагом
«не XML», так что из программы этот путь закрыт без правки драйвера pyttsx3.
Голос используется как запасной, вкладываться в него не стоит.
