# Генератор картинок: как подключить приложение с телефона

Сервер генерации живёт на станции отдельным контейнером и говорит обычным
HTTP + JSON. Никакого своего протокола, ни сокетов, ни очередей — телефонному
приложению достаточно уметь `POST` с JSON и читать байты ответа.

Этот же контракт использует настольное приложение Anima, так что телефон становится вторым
равноправным клиентом, а не «второй реализацией».

---

## 1. Адрес и доступ

| | |
|---|---|
| В домашней сети | `http://192.168.50.50:8770` |
| Через Tailscale | `http://100.79.130.7:8770` |

**Проверки подлинности нет.** Ни токена, ни пароля: кто дотянулся до порта —
тот и генерирует. Пока порт доступен только из домашней сети и из вашей сети
Tailscale, это осознанный размен на простоту. **Не пробрасывайте 8770 наружу
через роутер** — там сразу понадобится токен, которого в сервере нет.

Для телефона правильный путь — **Tailscale**: он же даёт доступ вне дома, и
адрес не меняется.

---

## 2. Самое короткое, что вообще работает

```bash
curl -X POST http://100.79.130.7:8770/generate \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "1girl, solo, portrait, masterpiece, high score"}' \
  --output out.png
```

Ответ — **сами байты PNG**, а не ссылка и не base64. Тело ответа пишется в файл
или в память как есть.

Ошибка приходит с кодом 500 и телом `{"error": "..."}` — текст уже
человеческий, его можно показывать пользователю без перевода.

## 3. Запрос генерации

`POST /generate`, `Content-Type: application/json`.

| Поле | Тип | По умолчанию | Что делает |
|---|---|---|---|
| `prompt` | строка | — обязательное | Запрос. Теговый для моделей этой ветки |
| `negative` | строка | список авторов модели | Чего в кадре быть не должно |
| `width`, `height` | число | 1024 | Размер кадра. Только родные пропорции (см. §7) |
| `steps` | число | 28 | Сколько раз модель уточняет кадр |
| `cfg` | число | 5 | Сила подсказки. При `1` негативный запрос НЕ работает |
| `sampler` | строка | `euler_a` | `euler_a`, `euler`, `dpmpp_2m`, `dpmpp_2m_karras`, `ddim` |
| `seed` | число | случайное | Зерно. Один и тот же запрос с одним зерном даёт один и тот же кадр |
| `model` | строка | текущая | Имя файла чекпоинта (см. `/models`) |
| `loras` | список | пусто | `[{"name": "файл.safetensors", "weight": 0.8}]` |
| `face` | число | 0 | Второй проход по лицу, сила 0…0,75. `0` — не делать |
| `hires` | число | 0 | Увеличить кадр во столько раз с дорисовкой. `0` или `1` — не увеличивать |
| `tile` | число | само | Порезка декодера: `0` — считать целиком, число — плитки. Обычно не нужно |
| `who` | строка | пусто | Кто просит. Нужно, только если вы сами держите заявку на карту (§9) |

Пример со всем сразу:

```json
{
  "prompt": "1girl, solo, full body, city, night, masterpiece, high score, great score",
  "negative": "lowres, bad anatomy, worst quality, blurry, watermark",
  "width": 832, "height": 1216,
  "steps": 28, "cfg": 5, "sampler": "euler_a",
  "face": 0.4, "hires": 1.5,
  "loras": [{"name": "detail-tweaker.safetensors", "weight": 0.6}]
}
```

### Сколько ждать

Замеры на станции (карта 16 ГБ, Animagine XL, кадр 832×1216, 28 шагов):

| | время |
|---|---|
| обычный кадр | ~47 с |
| + проход по лицу | ~53 с |
| + увеличение в 1,5 раза | ~94 с |
| первый кадр после простоя | +15 с на загрузку весов |

**Ставьте таймаут не меньше 20 минут.** На телефоне это значит: запрос в фоне,
а не в обработчике нажатия.

## 4. Ход генерации

Кадр считается минуту и больше, и молчаливое ожидание неотличимо от зависания.
Ход отдаётся **отдельным запросом**, а не в потоке картинки — так контракт
`/generate` остаётся простым.

```
GET /progress
{"running": true, "step": 12, "total": 28, "elapsed": 21.4, "stage": "",
 "hold": {"who": "", "note": "", "left": 0}}
```

`stage` непустой на дополнительных проходах: `"увеличение"`, `"лицо 1 из 2"`.
Если он начинается со слова «ждём», кадр стоит не в счёте, а в очереди за
соседом по видеокарте — что это значит и что показывать, см. §9.

Опрашивайте раз в секунду, пока ждёте ответ на `/generate`.

---

## 5. Очередь

**Сервер считает по одному кадру за раз** — карта одна. Второй одновременный
запрос не падает, а честно ждёт своей очереди и вернётся своей картинкой.

Это значит: телефон может отправлять несколько запросов подряд, не дожидаясь
предыдущего. Но `/progress` при этом показывает **текущий** кадр, не ваш, —
если очередь свою вы держите на телефоне, показывайте в ней «ждёт очереди» до
тех пор, пока ваш запрос не начал считаться.

Кадр может ждать не только другого кадра, но и разговора на компьютере — см.
§9. Внешне это то же ожидание, а причина другая, и человеку её лучше назвать.

## 6. Модели и довески

```
GET  /models                 что лежит на станции, что выбрано, сколько места
POST /models/select          {"model": "имя.safetensors"}
POST /models/pull            {"url": "https://...", "name": "имя.safetensors"}
GET  /models/pull            ход скачивания
POST /models/pull/cancel     прервать
POST /models/delete          {"model": "имя.safetensors"}
POST /models/note            {"model": ..., "note": {...}} рекомендации авторов

GET  /loras                  довески на станции
POST /loras/pull             {"url": ..., "name": ...}
POST /loras/delete           {"name": ...}
```

Ответ `/models`:

```json
{
  "dir": "/models",
  "free": 23622320128,
  "current": "animagine-xl-4.0-opt.safetensors",
  "items": [{
    "name": "animagine-xl-4.0-opt.safetensors",
    "size": 6938350040,
    "distilled": false,
    "note": {"cfg": 5, "steps": 28, "sampler": "euler_a", "prompt_style": "tags"}
  }]
}
```

- `distilled` — догадка по имени файла: у ускоренных моделей (turbo, lightning)
  сила подсказки равна единице, и негативный запрос у них **не участвует в
  счёте**. Поле для него в интерфейсе стоит гасить, а не делать вид.
- `note` — рекомендации авторов из карточки модели, если они известны. Пусто —
  значит неизвестны; выдумывать их за авторов не надо.

**Скачивает станция, а не телефон.** Файл в семь гигабайт незачем гонять через
телефон; закрытое приложение загрузку не прервёт, а открытое снова покажет её
ход через `GET /models/pull`.

## 8. Состояние и видеопамять

```
GET /health
{"engine": "sdxl", "loaded": true, "device": "видеокарта",
 "model": "animagine-xl-4.0-opt.safetensors",
 "vram_used_mb": 7930, "vram_total_mb": 16304,
 "torch_alloc_mb": 6815, "torch_reserved_mb": 7140,
 "idle_unload_sec": 600}

POST /load     занять видеопамять заранее
POST /unload   освободить
```

**Про соседей по карте.** На станции одна видеокарта, и языковая модель с
генератором на ней не помещаются. Сервер **сам** просит соседей отойти перед
загрузкой весов — телефону об этом заботиться не нужно и звать `/unload` перед
генерацией не надо. Обратный случай — когда карту в этот момент держит
компьютер — разобран в §9.

Обратная сторона: пока идёт генерация, языковая модель выгружена, и голосовой
помощник на это время замолкает. Если телефон умеет и то и другое — стоит
сказать об этом человеку, а не оставлять его гадать.

`POST /unload` дожидается конца текущего кадра, а не выдёргивает модель из-под
него.

## 9. Кто занимает видеокарту

Карта на станции одна, 16 ГБ, и желающих двое: языковая модель (~8 ГБ) и
генератор картинок (~7 ГБ с довесками). Вместе они не помещаются — не «работают
медленнее», а не помещаются.

Сервер картинок с самого начала умел отодвигать соседей: перед загрузкой весов
он просит Ollama и синтез речи освободить память. Обратной стороны у этого не
было, и получалось несимметрично: **пока телефон считал кадр, разговор на
компьютере упирался в занятую карту.** Ollama грузила модель поверх картинок,
не помещалась и уходила считать на процессор, а следующий кадр с телефона
выгонял её посреди ответа.

Поэтому у карты теперь есть **заявка**: «карта моя на столько-то секунд».

```
GET  /gpu                    кто держит карту сейчас
POST /gpu/hold               {"who": "...", "note": "...", "sec": 90}
POST /gpu/release            {"who": "..."}
```

**`/gpu/hold` возвращается тогда, когда карта действительно свободна.** Если в
этот момент считался кадр — запрос ждёт его конца и только потом отвечает:
оборвать чужую минуту счёта ради своей секунды — обмен не в ту сторону. На
станции это измерено: заявка, поданная на пятом шаге из двадцати, вернулась
через 32 секунды, кадр при этом досчитался целым.

| Поле | Что это |
|---|---|
| `who` | Кем подписана заявка. По нему же она снимается. Служебное имя, не для показа |
| `note` | Человеческое пояснение — вот его и показывают на другой стороне |
| `sec` | На сколько секунд. Не больше 600 |

**Срок — не формальность.** Заявку снимает тот, кто её взял, а он может до
этого не дожить: закрыли окно, оборвалась сеть, упало приложение. Без срока
карта осталась бы занятой навсегда. Держите заявку короткой и **продлевайте**
её тем же `/gpu/hold` (это не создаёт вторую заявку, а сдвигает срок первой).
Anima на компьютере берёт 90 секунд и продлевает каждые 45.

Чужую заявку `/gpu/release` не снимает: телефон, закрывая свой экран, не должен
обрывать ответ на компьютере.

### Что видит телефон, пока карту держат

`/generate` в это время **не отказывает, а ждёт**. Ждущий запрос виден в
`/progress` — там же, где обычный ход кадра:

```json
{"running": true, "step": 0, "total": 0, "stage": "ждём: компьютер (разговор с языковой моделью)",
 "hold": {"who": "desktop", "note": "компьютер (разговор с языковой моделью)", "left": 63.9}}
```

- `stage` начинается со слова «ждём» — значит, кадр стоит в очереди не за другим
  кадром, а за соседом по карте.
- `hold.note` — готовая строка для человека. Придумывать свою не нужно.
- `hold.left` — сколько секунд осталось заявке, если её не продлят.

Показать это стоит прямо на экране ожидания, вместо безликой полосы: «Компьютер
занял видеокарту (разговор с моделью). Кадр начнётся сам, ждать примерно минуту».
Разница между «оно висит» и «оно ждёт по понятной причине» — это разница между
закрытым приложением и спокойным ожиданием.

Поле `hold` есть и в `/health` — на случай, если экран показывает состояние
станции, а не ход конкретного кадра.

### Если карту берёт сам телефон

Заявку может подать и телефон — например, под серию кадров подряд, чтобы
компьютер не влез в середину. Тогда в `/generate` **добавьте то же `who`**:

```json
{"prompt": "...", "who": "phone"}
```

Без него запрос встанет в очередь к собственной заявке и простоит до конца её
срока. С ним — идёт считаться сразу; чужие заявки он по-прежнему ждёт.

### Что делает Anima на компьютере

Знать это полезно: телефон будет видеть последствия.

- Перед **каждым** ответом модели Anima подаёт заявку и снимает её после ответа.
  Пока идёт чужой кадр, на компьютере висит полоса «Телефон дорисовывает кадр —
  отвечу, как только он закончится», с номером шага.
- Если сервер картинок не отвечает за две секунды, Anima не ждёт вовсе и просто
  разговаривает: разговор не должен зависеть от выключенной станции.
- Свои запросы на генерацию Anima подписывает `who: desktop` — тем же именем, что
  и заявку.

### Проверено на станции

Сценарий из жизни, целиком, с замерами:

| | |
|---|---|
| телефон начал кадр | — |
| компьютер попросил карту на 5-м шаге | ответ через **32 с**, кадр досчитался целым (1,5 МБ) |
| после заявки | `loaded: false`, веса сняты с карты |
| компьютер спросил модель | ответ за **14 с** (с загрузкой модели) |
| телефон послал следующий кадр | ждёт: `stage: "ждём: компьютер…"` |
| языковая модель в это время | **осталась на карте** — раньше её выгоняли |
| компьютер отпустил карту | кадр досчитался сам, картинка пришла через 65 с |

## 10. Заготовка клиента

### Kotlin (Android, OkHttp)

```kotlin
val json = """{"prompt":"$prompt","width":832,"height":1216,"steps":28,"cfg":5}"""
val req = Request.Builder()
    .url("http://100.79.130.7:8770/generate")
    .post(json.toRequestBody("application/json".toMediaType()))
    .build()

val client = OkHttpClient.Builder()
    .callTimeout(20, TimeUnit.MINUTES)   // кадр считается минутами
    .build()

client.newCall(req).execute().use { resp ->
    if (!resp.isSuccessful) {
        val err = resp.body?.string()   // {"error": "..."} — текст уже читаемый
        return@use
    }
    val bytes = resp.body!!.bytes()     // это PNG целиком
    File(dir, "img-${System.currentTimeMillis()}.png").writeBytes(bytes)
}
```

Ход — параллельным опросом:

```kotlin
while (generating) {
    val p = JSONObject(get("$base/progress"))
    onProgress(p.optInt("step"), p.optInt("total"), p.optString("stage"))
    delay(1000)
}
```

### Flutter (Dart)

```dart
final res = await http
    .post(Uri.parse('$base/generate'),
        headers: {'Content-Type': 'application/json'},
        body: jsonEncode({
          'prompt': prompt,
          'width': 832, 'height': 1216,
          'steps': 28, 'cfg': 5, 'sampler': 'euler_a',
          if (face > 0) 'face': face,
        }))
    .timeout(const Duration(minutes: 20));

if (res.statusCode != 200) {
  throw Exception(jsonDecode(utf8.decode(res.bodyBytes))['error']);
}
await File(path).writeAsBytes(res.bodyBytes);   // res.bodyBytes — это PNG
```

## 11. Три ошибки, на которых уже спотыкались

1. **Слишком короткий таймаут.** Кадр 1024×1024 с увеличением идёт полторы
   минуты, первый после простоя — дольше. Таймаут в 30 секунд обрывает
   генерацию, которая на станции продолжает считаться.
2. **Довесок, которого больше нет.** Если довесок удалили со станции, а
   приложение всё ещё шлёт его в `loras`, каждый запрос будет падать с
   `{"error": "нет довеска: имя"}`. Сверяйте выбор со списком `/loras` при
   открытии экрана, а при этой ошибке — выкидывайте пропавший и повторяйте.
3. **Ожидание отправки числа в `{N}`-подстановке.** Сервер подстановок не
   делает: что прислали в `prompt`, то и считается.

## 12. Развёртывание сервера

Если станцию поднимают заново:

```bash
scp -r server/image user@станция:~/evs-image
ssh user@станция 'bash ~/evs-image/deploy-image.sh --rebuild'
```

Скрипт отказывается работать без видеокарты, проверяет место, поднимает
контейнер и **заканчивается настоящей генерацией** — если картинка не вышла,
у приложения она тоже не выйдет, сколько бы контейнер ни рапортовал «healthy».
