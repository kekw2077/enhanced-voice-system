# Windows-специфика

Дополнение к [CLAUDE.md](CLAUDE.md): подробности, которые нужны редко, но при
столкновении с ними стоят часа поиска. Карта проекта, правила и выпуск — там,
здесь только то, что относится именно к Windows.

## Сборка и смоук

```powershell
flutter run -d windows              # запуск с отладкой
flutter build windows --release     # → build\windows\x64\runner\Release\anima.exe
flutter build windows --debug       # дебаг-сборка для быстрой проверки
```

Смоук-проверка: собрать, запустить `anima.exe`, дождаться окна. Окно и виджет не
показываются, пока движок не ответил `ready` — «долго не появляется» обычно значит
проблему в движке, а не в интерфейсе.

## Три процесса

| Процесс | Что это |
|---|---|
| `anima.exe` | само приложение |
| `anima_sidecar.exe` | голосовой движок на Python (в разработке — `python sidecar/main.py`) |
| `anima_widget.exe` | плавающий виджет визуализации, отдельным процессом |

Виджет запускается как **копия** исполняемого файла под своим именем, чтобы в
диспетчере задач было видно, за что он отвечает. Старые копии (`evs_widget.exe`)
подметаются при запуске — иначе обновление не сможет заменить файлы.

Единственность копии держит мьютекс `EVS-SingleInstance-Mutex` (плюс порт 47653).
Имя мьютекса менять нельзя: две копии ассистента с двумя движками на один микрофон —
это не «дубль окна», а сломанный звук. Осиротевшие после падения `anima_sidecar.exe` и
`evs_sidecar.exe` подметаются в [lib/src/bootstrap.dart](lib/src/bootstrap.dart).

## Где лежат данные

Корень данных **портативный**: `<папка установки>\userdata`. Запасной путь для старых
установок — `%APPDATA%\com.example\EVS` (`legacyDataRoot()`), пока данные лежат там.

**На системный диск не писать ничего.** Кэши моделей пиннятся явно (`pin_cache_to` в
[sidecar/qwen_tts_server.py](sidecar/qwen_tts_server.py) — `HF_HOME`, `HF_HUB_CACHE`,
`TORCH_HOME`, `TMP`/`TEMP`). Непрочитанная переменная окружения не даёт ошибки — она
молча уводит четыре гигабайта весов на `C:`.

Команды с правами администратора выполняются через задачу планировщика
(`elevatedTaskName` → папка `EVS\cmd_*`). Имя папки не переименовывать: там уже лежат
задачи, созданные пользователем.

## Потолок контекста локальной модели

`AppState.ramContextCeiling` подбирает максимум контекста по объёму ОЗУ, а ОЗУ читается
плагином `system_info_plus` — **он не поддерживает Windows**. Вызов молча падает в
`catch`, `deviceRamMb` остаётся `null`, и потолок становится жёсткими **4096**
независимо от того, сколько памяти в машине на самом деле.

Для ПК это занижено, но **чинить не нужно, и это решение, а не недосмотр**: локальные
модели на Windows не используются — весь инференс идёт на станции. Экран «Локальные
модели» и каталог `kLocalModels` остаются в коде, но реального применения у них здесь
нет, и занижённый потолок ни на что не влияет.

Если однажды понадобится: читать ОЗУ напрямую (Win32 `GlobalMemoryStatusEx` через
`dart:ffi` или `Process.run` с PowerShell) либо развязать логику под
`Platform.isWindows`. Потолок применяется в **трёх** местах, править надо во всех:
элемент выбора контекста в настройках, вкладка ролевой игры и защитный клэмп в
`LocalLLMService._buildRequest`.

## Локальный инференс (fllama)

Пакет — **Telosnex/fllama**, git-зависимость, закреплённая на конкретный commit SHA в
`pubspec.yaml` (одноимённый пакет на pub.dev — другой, не он). На Windows llama.cpp
собирается через CMake при первой сборке; результат кэшируется в
`~/.cache/fllama/<hash>/` — это вне `.dart_tool`, поэтому переживает `flutter clean`.

Чего в закреплённой версии нет и не появится без форка: полей `stop`, `mirostat`,
`tfs_z`, `typical_p` в `OpenAiRequest`; API выгрузки модели из памяти; ловимого
исключения при нехватке памяти. Стоп-последовательности нативно умеет только Ollama.

## Иконки

Внутри приложения и снаружи — **намеренно разные знаки**, сводить их к одному не надо.

- **В приложении — Genesis**: заставка, марка в углу, «О программе». Рисуется кодом
  ([lib/src/genesis_logo.dart](lib/src/genesis_logo.dart)), не картинкой.
- **Системные иконки** (exe, ярлык, трей, установщик) — отдельный знак, готовые файлы
  лежат в `assets/icon/app_icon.ico` (трей) и `windows/runner/resources/app_icon.ico`.
- `assets/icon/gen_system_icons.py` разбирает SVG собственным парсером под **старую**
  форму (полосы эквалайзера) и на новом знаке рисовал бы бессмыслицу — поэтому скрипт
  теперь отказывается работать. Это защита, а не поломка.
- У `flutter_launcher_icons` windows-таргет выключен: иначе он перезапишет системную
  иконку знаком Genesis.

## Мелочи интерфейса

- Глобальный шрифт — **Nunito**, подключён как asset, а не через `google_fonts`:
  иначе шрифт качался бы по сети при первом запуске, что противоречит офлайн-работе.
- `BackdropFilter` и стекло на Windows работают штатно.
- Оболочек четыре (`AppStyle { standard, nexus, noctur, prism }`), и «Призма» держит
  студии вкладками, а не окнами — тексты про «закройте окно» там неверны, для неё
  предусмотрены отдельные строки локализации.
