# Переименование EVS → Nexus Anima

Порядок важен: сначала внутренние идентификаторы, потом пользовательские данные, в последнюю очередь внешние каналы. Если сделать наоборот, приложение потеряет свой конфиг и отвалится от телефона.

Соглашение по именам, чтобы не путаться:

| Где | Значение |
|---|---|
| Отображаемое имя | `Nexus Anima` |
| Короткое имя, wake word, разговорное | `Anima` |
| Идентификатор в коде, папках, пакетах | `anima` |
| Dart-пакет | `anima` |
| Python-пакет сайдкара | `anima_core` |

---

## 1. Ветка и точка возврата

```bash
git switch -c rename/anima
git tag pre-rename-evs        # точка отката, если миграция конфига пойдёт не так
```

Пока репозиторий отстаёт от рабочей копии, сначала залей текущее состояние, иначе переименование смешается с месяцем несохранённых правок и разобрать конфликт будет невозможно.

---

## 2. Flutter: идентификаторы

| Файл | Что менять |
|---|---|
| `pubspec.yaml` | `name: evs` → `name: anima`. Это ломает **все** импорты вида `package:evs/...` |
| `lib/**/*.dart` | Массовая замена импортов, см. команду ниже |
| `windows/CMakeLists.txt` | `set(BINARY_NAME "evs")` → `"anima"` |
| `windows/runner/main.cpp` | Заголовок окна в `window.Create(L"...")` → `Nexus Anima` |
| `windows/runner/Runner.rc` | `FileDescription`, `ProductName`, `InternalName`, `OriginalFilename` |
| `windows/runner/resources/app_icon.ico` | Заменить на новый `anima-icon.ico` |
| `android/app/build.gradle` | `applicationId`, если мобильная часть шарит код |

Импорты:

```bash
grep -rl "package:evs/" lib test | xargs sed -i 's|package:evs/|package:anima/|g'
flutter clean && flutter pub get && flutter analyze
```

## 3. Сайдкар

| Что | Было | Стало |
|---|---|---|
| Папка пакета | `evs_core/` | `anima_core/` |
| Точка входа | `python -m evs_core` | `python -m anima_core` |
| PyInstaller spec | `evs-sidecar.spec` | `anima-sidecar.spec` |
| Имя exe | `evs-sidecar.exe` | `anima-sidecar.exe` |
| Путь запуска из Flutter | обновить строку запуска процесса | |

Заодно, раз всё равно трогаешь: смени схему версий с `v27` на семвер и научи сайдкар сообщать версию в хендшейке. Тогда UI сможет проверять совместимость сам, а не полагаться на то, что рядом лежит правильный файл.

---

## 4. Данные пользователя — самое опасное место

Всё, что лежит в `%APPDATA%\EVS`, надо перенести, а не бросить. Иначе пользователь (то есть ты) откроет приложение и увидит чистый конфиг, пустую историю и заново неподключенный сайдкар.

Что там обычно лежит: `config.json`, база событий, база памяти, логи, кэш моделей, сохранённые темы.

Однократная миграция при старте:

```python
from pathlib import Path
import os, shutil

OLD = Path(os.environ["APPDATA"]) / "EVS"
NEW = Path(os.environ["APPDATA"]) / "NexusAnima"

def migrate() -> None:
    if NEW.exists() or not OLD.exists():
        return
    shutil.copytree(OLD, NEW)          # копируем, не переносим
    (NEW / ".migrated-from-evs").write_text(str(OLD), encoding="utf-8")
    # старую папку не удаляем: пусть полежит до следующего релиза
```

Копия, а не перенос — сознательно. Если что-то пойдёт не так, старая папка на месте и можно откатиться тегом.

Внутри конфига поискать захардкоженные пути со словом EVS: они переживут переезд папки и будут указывать в никуда.

## 5. Реестр и автозапуск

| Ключ | Действие |
|---|---|
| `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` | Значение `EVS` удалить, создать `NexusAnima` с новым путём |
| `HKCU\Software\EVS` | Перенести содержимое в `HKCU\Software\NexusAnima`, старое удалить |
| Ярлык в папке Startup | Пересоздать, если автозапуск сделан через него |
| Имя мьютекса единственного экземпляра | Сменить, иначе старая и новая сборка будут считать друг друга собой |

## 6. Внешние каналы

**ntfy.** Смена топика разрывает связь с телефоном. Правильный порядок: сайдкар какое-то время слушает **оба** топика, мобильное приложение переключается на новый, через пару недель старый выключается.

```yaml
ntfy:
  topics:
    primary: anima-pc
    legacy:  evs-pc      # удалить после переключения телефона
```

**Мобильное приложение.** Если решишь довести до конца идею с Nexus Hub — делай это отдельной задачей, не смешивая с этим переименованием. Два переименования в одном коммите невозможно откатить по частям.

---

## 7. Мелочи, которые забываются

- Тултип иконки в трее и заголовки уведомлений
- Имя приложения в окне «О программе» и в инсталляторе
- User-Agent или client id в запросах к Ollama
- Имена лог-файлов и их ротация
- Заголовки окна оверлея CZN
- Название темы `Nexus Sync` внутри приложения — если имя уходит мобильному, переименуй тему заранее

Wake word (`айрис`) не трогать: это рантайм-настройка, к имени продукта отношения не имеет.

## 8. Проверка

```bash
grep -rin "evs" --include="*.dart" --include="*.py" --include="*.yaml" \
     --include="*.cmake" --include="*.rc" . | grep -v "\.git/"
```

Ложные срабатывания будут: `evs` встречается внутри обычных слов. Смотреть глазами, не автозаменять.

Финальный тест по пунктам:

1. Чистая сборка проходит, `flutter analyze` молчит.
2. Приложение стартует, сайдкар подключается, в хендшейке новая версия.
3. Настройки и история на месте — миграция сработала.
4. Автозапуск после перезагрузки работает, старый ключ не остался.
5. Пуш с телефона доходит.
6. Иконки в окне, на панели задач и в трее — новые (проверить после перезагрузки: Windows кэширует иконки).

Если кэш иконок залип:

```powershell
ie4uinit.exe -show
```
